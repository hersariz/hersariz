## 🤖 How I work with AI

AI coding agents are my daily working method, not an experiment.

| | |
|---|---|
| **Plan first** | Every feature starts as a short spec in plain English — what changes, what must not change, the edge cases I can already see. |
| **Agents do the mechanical layer** | Codex daily, Claude Code alongside it: scaffolding, API wiring, wide refactors, first-draft docs. |
| **I keep what carries risk** | Data models, API contracts, anything near auth or payments, every architecture decision. |
| **Nothing ships unreviewed** | I read every diff line by line, the way I'd review a junior's PR — and I send plenty back. |

<details>
<summary><b>Why the review step is not optional</b> — a story</summary>

<br/>

An agent once wrote a query against our GraphQL API that looked perfect. Sensible field names, types included, nothing flagged in the editor. Two of those fields did not exist — it had inferred them from naming patterns and then hand-written its own type definitions, which is exactly why nothing complained. I found it in manual QA when the values came back `null`.

The quick fix was rewriting the query. The useful fix was a rule: **agents may only import types generated from the real schema, never declare their own.** After that, an invented field fails the build instead of reaching production.

A model sounds exactly as confident when it's wrong as when it's right. Confidence isn't evidence — verification is the whole job.

</details>
